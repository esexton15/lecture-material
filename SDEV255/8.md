# Part 1: Conditional Rendering and Lists

---

## Conditional Rendering: The Basics

In React, you use JavaScript to decide what to render.

**Ternary operator:**

```jsx
function Status({ isComplete }) {
  return <span>{isComplete ? "Done" : "Pending"}</span>;
}
```

If `isComplete` is true, render "Done". Otherwise, render "Pending".

<!--
Lecture notes:
- Show in browser: toggle a boolean and see the text change.
- This is pure JavaScript inside JSX.
-->

---

## Conditional Rendering with &&

The `&&` operator is useful for showing/hiding elements:

```jsx
function TaskItem({ task }) {
  return (
    <div>
      <h3>{task.title}</h3>
      {task.isComplete && <span className="badge">Complete</span>}
    </div>
  );
}
```

When `task.isComplete` is true, the badge appears. When false, nothing renders.

<!--
Lecture notes:
- Common pattern for optional UI elements.
- Warning: don't use `&&` with numbers that could be 0 (0 renders as "0").
-->

---

## Rendering Lists with .map()

Use JavaScript's `.map()` to transform an array of data into an array of JSX elements:

```jsx
function TaskList({ tasks }) {
  return (
    <ul>
      {tasks.map((task) => (
        <li key={task.id}>{task.title}</li>
      ))}
    </ul>
  );
}
```

Each item in the array becomes a JSX element.

<!--
Lecture notes:
- Compare to a for loop, but emphasize .map() returns a new array.
- React renders arrays of elements automatically.
-->

---

## The Key Prop

Every list item needs a unique **key** prop:

```jsx
{
  tasks.map((task) => <li key={task.id}>{task.title}</li>);
}
```

Why keys matter:

- React uses keys to track which items changed, added, or removed
- Keys must be unique among siblings
- Using the array index as key is a fallback, but not ideal

**Best practice:** Use stable IDs from your data (like `task.id`).

<!--
Lecture notes:
- Show what happens without a key (React warning in console).
- Explain: keys are for React's internal tracking, not for display.
-->

---

## Empty State Handling

Show a message when the list is empty:

```jsx
function TaskList({ tasks }) {
  if (tasks.length === 0) {
    return <p>No tasks yet. Add one above!</p>;
  }

  return (
    <ul>
      {tasks.map((task) => (
        <li key={task.id}>{task.title}</li>
      ))}
    </ul>
  );
}
```

Early return is a clean pattern for empty states.

<!--
Lecture notes:
- Show both states: empty list and populated list.
- This improves user experience significantly.
-->

# Part 2: Forms and Controlled Components

---

## Controlled Inputs

A **controlled input** is an input whose value is controlled by React state:

```jsx
function NameForm() {
  const [name, setName] = useState("");

  return <input value={name} onChange={(e) => setName(e.target.value)} />;
}
```

- `value={name}` - React controls what's displayed
- `onChange` - React updates state when user types
- State is the **single source of truth**

<!--
Lecture notes:
- Type in the input and show state updating in real-time.
- This is different from traditional HTML forms.
-->

---

## Why Controlled Components?

With controlled components:

- React state is the source of truth
- You can validate on every keystroke
- You can transform input as user types
- You can disable/enable buttons based on form state

The input displays what's in state. State changes when input changes.

<!--
Lecture notes:
- Show: if you change state programmatically, the input updates.
- This enables powerful form patterns.
-->

---

## Handling Form Submission

```jsx
function AddTaskForm({ onAddTask }) {
  const [title, setTitle] = useState("");

  function handleSubmit(e) {
    e.preventDefault();
    if (title.trim()) {
      onAddTask(title);
      setTitle("");
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={title}
        onChange={(e) => setTitle(e.target.value)}
        placeholder="Enter task title"
      />
      <button type="submit">Add Task</button>
    </form>
  );
}
```

`e.preventDefault()` stops the page from reloading.

<!--
Lecture notes:
- Show what happens without preventDefault (page reload).
- This is essential for SPA behavior.
-->

---

## Multiple Inputs Pattern

Use one state object for multiple fields:

```jsx
function TaskForm() {
  const [formData, setFormData] = useState({
    title: "",
    priority: "normal",
  });

  function handleChange(e) {
    const { name, value } = e.target;
    setFormData((prev) => ({
      ...prev,
      [name]: value,
    }));
  }

  return (
    <form>
      <input name="title" value={formData.title} onChange={handleChange} />
      <select name="priority" value={formData.priority} onChange={handleChange}>
        <option value="low">Low</option>
        <option value="normal">Normal</option>
        <option value="high">High</option>
      </select>
    </form>
  );
}
```

<!--
Lecture notes:
- The computed property name `[name]: value` is key.
- This scales to many fields with one handler.
-->

---

## Form Validation in React

Validate on change and/or on submit:

```jsx
function TaskForm({ onAddTask }) {
  const [title, setTitle] = useState("");
  const [error, setError] = useState("");

  function handleSubmit(e) {
    e.preventDefault();

    if (title.trim().length < 3) {
      setError("Title must be at least 3 characters");
      return;
    }

    onAddTask(title);
    setTitle("");
    setError("");
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={title}
        onChange={(e) => {
          setTitle(e.target.value);
          if (e.target.value.length >= 3) {
            setError("");
          }
        }}
      />
      {error && <p className="error">{error}</p>}
      <button type="submit">Add</button>
    </form>
  );
}
```

<!--
Lecture notes:
- Show validation triggering and clearing.
- Discuss: when to validate (on change, on blur, on submit).
-->

# Part 3: Fetching Data with useEffect

---

## The useEffect Hook

`useEffect` lets you run code after the component renders.

It's commonly used for:

- Fetching data from APIs
- Setting up subscriptions
- Timers and intervals
- Any "side effect" outside the component

```jsx
import { useEffect, useState } from "react";

function DataFetcher() {
  const [data, setData] = useState(null);

  useEffect(() => {
    // This runs after the component renders
    fetchData().then(setData);
  }, []); // Empty array = run once on mount

  return <div>{data ? data.name : "Loading..."}</div>;
}
```

<!--
Lecture notes:
- Emphasize: useEffect runs AFTER render, not during.
- The dependency array controls when it re-runs.
-->

---

## Fetching Data on Mount

The most common pattern - fetch when component first appears:

```jsx
function TaskList() {
  const [tasks, setTasks] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    fetch("/api/tasks")
      .then((res) => {
        if (!res.ok) throw new Error("Failed to fetch");
        return res.json();
      })
      .then((data) => {
        setTasks(data);
        setLoading(false);
      })
      .catch((err) => {
        setError(err.message);
        setLoading(false);
      });
  }, []); // Empty array = run once

  // ... render
}
```

<!--
Lecture notes:
- Walk through each step: fetch, check status, parse JSON, update state.
- Show the loading state appearing and disappearing.
-->

---

## Loading and Error States

Always handle loading and error states:

```jsx
function TaskList() {
  const [tasks, setTasks] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  // ... fetch logic

  if (loading) return <p>Loading tasks...</p>;
  if (error) return <p>Error: {error}</p>;

  return (
    <ul>
      {tasks.map((task) => (
        <li key={task.id}>{task.title}</li>
      ))}
    </ul>
  );
}
```

Users should never see a broken or frozen UI.

<!--
Lecture notes:
- Show what happens without error handling (app crashes).
- This is essential for production-ready apps.
-->

---

## The Dependency Array

The second argument to `useEffect` controls when it runs:

```jsx
// Run once on mount
useEffect(() => {
  fetchData();
}, []);

// Run when 'id' changes
useEffect(() => {
  fetchUserData(id);
}, [id]);

// Run on every render (avoid this!)
useEffect(() => {
  console.log("Rendered!");
});
```

**Rule:** Include all values from the component scope that the effect uses.

<!--
Lecture notes:
- Show the infinite loop that happens with missing dependencies.
- This is a common bug for beginners.
-->

---

## Async/Await with useEffect

For cleaner async code, define an async function inside the effect:

```jsx
useEffect(() => {
  async function fetchTasks() {
    try {
      const response = await fetch("/api/tasks");
      if (!response.ok) throw new Error("Failed to fetch");
      const data = await response.json();
      setTasks(data);
    } catch (err) {
      setError(err.message);
    } finally {
      setLoading(false);
    }
  }

  fetchTasks();
}, []);
```

Note: `useEffect` itself cannot be async, but you can call async functions inside it.

<!--
Lecture notes:
- Show both Promise chain and async/await versions.
- Async/await is generally more readable for complex logic.
-->

# Part 4: Component Composition Patterns

---

## The Children Prop

Components can receive nested content via `children`:

```jsx
function Card({ children }) {
  return <div className="card">{children}</div>;
}

// Usage:
<Card>
  <h2>Task Title</h2>
  <p>Task description here</p>
</Card>;
```

`children` is a special prop that contains whatever is between the opening and closing tags.

<!--
Lecture notes:
- This pattern is used everywhere in React component libraries.
- It enables flexible, reusable layout components.
-->

---

## Lifting State Up

When two components need to share state, move that state to their closest common parent.

Problem: TaskForm and TaskList both need access to the tasks array.

Solution: Move `tasks` state to App, pass it down.

```jsx
function App() {
  const [tasks, setTasks] = useState([]);

  function handleAddTask(title) {
    setTasks([...tasks, { id: Date.now(), title }]);
  }

  return (
    <div>
      <TaskForm onAddTask={handleAddTask} />
      <TaskList tasks={tasks} />
    </div>
  );
}
```

<!--
Lecture notes:
- Draw the component tree showing state flowing down.
- This is called "lifting state up" and is a fundamental React pattern.
-->

---

## Prop Drilling

To pass data to deeply nested components, you pass props through each level:

```jsx
<App>
  {" "}
  // has user state
  <Header user={user} />
  <Main user={user}>
    <Sidebar user={user}>
      <Profile user={user} /> // finally uses user
    </Sidebar>
  </Main>
</App>
```

This is called **prop drilling**. It works, but gets tedious for deep trees.

Solution for larger apps: Context API (covered in future courses).

<!--
Lecture notes:
- For this course, prop drilling is acceptable.
- Mention Context exists but don't teach it today.
-->

---

## Sharing State Between Siblings

Siblings cannot share state directly. They must share through their parent:

```jsx
function App() {
  const [tasks, setTasks] = useState([]);

  return (
    <div>
      <TaskStats tasks={tasks} />      {/* Sibling 1 */}
      <TaskList tasks={tasks} />       {/* Sibling 2 */}
      <TaskForm onAddTask={...} />     {/* Sibling 3 */}
    </div>
  );
}
```

All three siblings read from or write to the same `tasks` state in App.

<!--
Lecture notes:
- This is why "lifting state up" is so important.
- Parent becomes the coordinator for sibling communication.
-->

## What Are Custom Hooks?

Custom hooks let you extract and reuse stateful logic.

Naming convention: functions starting with `use` are hooks.

```jsx
function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    fetch(url)
      .then((res) => res.json())
      .then(setData)
      .catch(setError)
      .finally(() => setLoading(false));
  }, [url]);

  return { data, loading, error };
}
```

<!--
Lecture notes:
- Custom hooks are just functions that use other hooks.
- They enable code reuse without repeating logic.
-->

---

## Using a Custom Hook

```jsx
function TaskList() {
  const { data: tasks, loading, error } = useFetch("/api/tasks");

  if (loading) return <p>Loading...</p>;
  if (error) return <p>Error: {error.message}</p>;

  return (
    <ul>
      {tasks.map((task) => (
        <li key={task.id}>{task.title}</li>
      ))}
    </ul>
  );
}
```

The fetch logic is now reusable across any component that needs it.
