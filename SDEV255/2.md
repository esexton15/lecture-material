# Part 1 - Client vs Server Concepts

---

## Server-Side vs Client-Side in Practice (LO 1-1, 1-2)

Server-side scripting (Node.js, PHP, Ruby):

- Request handling, auth, data access, business rules
- Returns HTML/JSON to clients

Client-side scripting (JavaScript in browser):

- Handles UI interactions and immediate feedback
- Updates DOM and calls APIs

Rule of thumb: trust boundary and data integrity stay on the server.

---

## Client vs Server: Key Capability Differences (LO 1)

| Client Side                     | Server Side                        |
| ------------------------------- | ---------------------------------- |
| Focus: user interaction         | Focus: data and business logic     |
| Can manipulate page UI directly | Can access DB and secure resources |
| User can inspect code           | Better place for sensitive logic   |

---

## Where Code Runs and Why It Matters (LO 1)

1. Browser sends request to server
2. Server processes data and returns HTML/JSON
3. Client-side JS updates the UI

Design rule:

- Put secure/data logic on server
- Put immediate interaction logic on client

---

## JavaScript on the Front End (LO 1-3)

Brendan Eich created JavaScript in 1995 for Netscape Navigator.
Original goal: let pages respond to user events.

Front-end use cases today:

- Button click interactions
- Form validation
- Dynamic page updates
- Interactive apps (maps, mail, dashboards)

---

JavaScript is also used outside the browser.
With Node.js, JavaScript can run server-side to:

- Handle HTTP requests
- Query databases
- Build APIs
- Manage auth/session logic

One language can now power both front end and back end.

---

## JavaScript Full-Stack Example (LO 1-3)

Example flow: Save a to-do item

- Client JS captures form input
- Server JS validates and stores in database
- Server returns updated item as JSON
- Client JS updates list on screen

Same language, two execution environments.

# Part 2 - Core JavaScript Building Blocks

---

## Variables and Data Types (LO 5, 5-1)

Variable = named container for a value in memory.

```javascript
let score;
score = 2;
let maxValue = 5;
const slicesPerPizza = 8;
```

- `let` declares variables
- `const` declares values that should not change

---

## Arithmetic Expressions and Operators (LO 5)

An expression combines values/operators and evaluates to one value.

```javascript
let x = 2;
let y = 2 * (x + 1); // 6
```

Core arithmetic operators:

- `+` add
- `-` subtract
- `*` multiply
- `/` divide
- `%` modulus (remainder)
- `**` exponent
- `++` increment, `--` decrement

Precedence reminder: use parentheses to make intent explicit.

```javascript
let a = 7 + 3 * 2; // 13
let b = (7 + 3) * 2; // 20
```

Compound assignments (common in loops/counters): `+=`, `-=`, `*=`, `/=`, `%=`.

---

## Numbers, Strings, and the `+` Operator (LO 5)

`+` can mean addition or string concatenation.

```javascript
2 + 3; // 5
"2" + "3"; // "23"
"2" + 3; // "23"
"back" + "pack"; // "backpack"
```

If one operand is a string, `+` concatenates.

---

## Numeric Conversion and NaN (LO 5)

```javascript
parseInt("5"); // 5
parseFloat("2.4"); // 2.4
parseInt("dog"); // NaN

isNaN(6); // false
isNaN("dog"); // true
isNaN("123"); // false
```

For non-`+` arithmetic operators, JavaScript often tries to convert strings to numbers:

```javascript
"2" * 3; // 6
```

---

## Arrays: Creation and Access (LO 5-3)

Array = ordered list of values.

```javascript
let teams = ["Broncos", "Cowboys", "49ers"];

console.log(teams[0]); // Broncos
teams[1] = "Bears";
```

Use arrays when you need multiple related values.

---

## Arrays in Real Use (LO 5-3)

```javascript
let tasks = ["Read", "Code", "Commit"];

tasks.push("Test");

for (let i = 0; i < tasks.length; i++) {
  console.log(tasks[i]);
}
```

Core array actions: create, access, update, loop through.

---

## Add and Remove Elements (LO 5-3)

```javascript
let nums = [2, 4, 6];

nums.push(8); // [2, 4, 6, 8]
nums.pop(); // removes last
nums.unshift(0); // add to front
nums.shift(); // remove first
```

These methods resize arrays as values are added/removed.

---

## splice() for Anywhere Edits (LO 5-3)

```javascript
let nums = [2, 4, 6, 8, 10];

nums.splice(3); // [2, 4, 6]
nums.splice(0, 2); // [6]
nums.splice(0, 0, 3, 5); // [3, 5, 6]
```

`splice(start, deleteCount, ...itemsToAdd)`

Use `splice()` when editing from the middle of an array.

---

## Looping Through Arrays (LO 5-3)

```javascript
let groceries = ["bread", "milk", "peanut butter"];

for (let i = 0; i < groceries.length; i++) {
  console.log(i + " - " + groceries[i]);
}
```

Use `length` to avoid hard-coding loop limits.

---

## for...of and forEach() (LO 5-3)

```javascript
for (let item of groceries) {
  console.log(item);
}

groceries.forEach(function (item, index) {
  console.log(index + " - " + item);
});
```

- `for...of`: clean value iteration
- `forEach()`: value + index with callback

---

## Passing Arrays to Functions (LO 5-3, 5-4)

Arrays can be passed as function arguments, and functions can modify them.

```javascript
function addTask(arr, task) {
  arr.push(task);
}

let tasks = ["Read"];
addTask(tasks, "Code");
```

After call, `tasks` is `["Read", "Code"]`.

---

## Searching Arrays (LO 5-3)

```javascript
let scores = [80, 92, 75, 64, 88, 92];

scores.indexOf(92); // 1
scores.indexOf(92, 2); // 5
scores.lastIndexOf(92); // 5
scores.indexOf(100); // -1
```

- `indexOf()` searches from front
- `lastIndexOf()` searches from back

---

## Sorting Arrays (LO 5-3)

Default `sort()` compares as strings (Unicode), which can be wrong for numbers.

```javascript
let numbers = [200, 30, 1000, 4];

numbers.sort(); // [1000, 200, 30, 4]

numbers.sort(function (a, b) {
  return a - b;
}); // [4, 30, 200, 1000]
```

For numeric sort, pass a comparison function.

## Control Structures (LO 5-1)

Control structures direct program flow.

```javascript
let score = 85;

if (score >= 70) {
  console.log("Pass");
} else {
  console.log("Retry");
}
```

Common structures: `if/else`, `for`, `while`.

---

## Comparison Operators (LO 5-1)

- `==` equality (with type conversion)
- `!=` inequality (with type conversion)
- `===` strict equality (value and type)
- `!==` strict inequality
- `<`, `<=`, `>`, `>=`

```javascript
2 == "2"; // true
2 === "2"; // false
```

Prefer `===` and `!==` in most cases.

---

## Common Equality Mistake

Do not confuse assignment `=` with comparison `==`/`===`.

```javascript
if ((name = "Sue")) {
  // BUG: assigns value instead of comparing
}
```

Correct:

```javascript
if (name === "Sue") {
  // compare safely
}
```

---

## Nested if vs else-if (LO 5-1)

When checking one variable against multiple ranges, `else if` is cleaner.

```javascript
if (score >= 90) {
  grade = "A";
} else if (score >= 80) {
  grade = "B";
} else if (score >= 70) {
  grade = "C";
} else if (score >= 60) {
  grade = "D";
} else {
  grade = "F";
}
```

---

## Logical Operators (LO 5-1)

- `&&` AND: both sides must be true
- `||` OR: at least one side true
- `!` NOT: flips true/false

```javascript
1 < 2 && 2 < 3; // true
1 < 2 || 2 < 0; // true
!(2 === 2); // false
```

---

## Complex Conditions and Best Practices

`&&` has higher precedence than `||`.

Use parentheses to make intent explicit:

```javascript
// Clearer
a < 0 || (a > 1 && b > 2);
```

Also avoid unnecessary NOT when possible:

```javascript
// Harder to read
!(score > 10);

// Clearer
score <= 10;
```

## while and do...while (LO 5-1)

```javascript
let i = 1;
while (i <= 3) {
  console.log(i);
  i++;
}

do {
  console.log(i);
  i++;
} while (i <= 5);
```

- `while`: check first, then run
- `do...while`: run once, then check

---

## for Loop (LO 5-1)

```javascript
for (let i = 1; i <= 3; i++) {
  console.log(i);
}
```

`for` keeps setup, condition, and update together at the top of the loop.

Avoid infinite loops by ensuring the loop condition can become false.

---

## break and continue (LO 5-1)

```javascript
for (let c = 1; c <= 5; c++) {
  if (c === 4) {
    continue;
  }
  console.log(c); // 1 2 3 5
}
```

- `break` exits loop immediately
- `continue` skips remaining statements and jumps to next iteration

Use jump statements carefully; they can hide logic bugs.

---

## User-Defined Functions (LO 5-4)

A function is a named group of statements.

```javascript
function calcArea(width, height) {
  return width * height;
}

let area = calcArea(5, 3);
console.log(area); // 15
```

Good naming style: verb + noun in camelCase, like `displayAverage`.

---

## Returning Values (LO 5-4)

- `return` sends one value back to caller
- A function with no `return` yields `undefined`

```javascript
function greet(name) {
  return "Hello, " + name;
}

function logName(name) {
  console.log(name);
}
```

---

## Function Expressions and Anonymous Functions

Functions can be assigned to variables.

```javascript
let displaySum = function (x, y, z) {
  console.log(x + y + z);
};

displaySum(2, 5, 3);
```

Unlike function declarations, call only after assignment.

---

## Arrow Functions

Arrow functions are compact anonymous functions.

```javascript
const multiply = (a, b) => a * b;

const showTotal = (x, y) => {
  let total = x + y;
  console.log(total);
};
```

Use concise form for short expressions and block form for multiple statements.

---

## Putting It Together: Small Script Walkthrough (LO 5)

```javascript
let names = ["Ava", "Kai", "Naya"];

function greet(name) {
  return "Hello, " + name;
}

for (let i = 0; i < names.length; i++) {
  console.log(greet(names[i]));
}
```

This combines arrays, loops, and user-defined functions.

---

## Scope: var vs let (LO 5)

Scope = where a variable can be accessed.

- Global scope: declared outside functions
- Local scope: declared inside functions
- `var` in function -> function scope
- `let` in braces -> block scope

```javascript
function demo() {
  if (true) {
    var a = 1;
    let b = 2;
  }
  console.log(a); // works
  // console.log(b); // error
}
```

---

## Global Object and Global Variables

In browsers, global variables may attach to `window`.

- `var x = 5;` can create `window.x`
- `let y = 5;` is global but not a `window` property
- Assigning undeclared variables can create accidental globals

Be careful: global names can collide with existing browser properties.

---

## Accidental Global Example

```javascript
function calculateTax(total) {
  // Missing declaration; becomes global
  tax = total * 0.06;
  return tax;
}

var totalTax = calculateTax(10);
console.log(tax); // 0.6
```

Best practice: always declare variables with `let`, `const`, or `var`.

---

## Identifier Rules and Naming Style

Identifiers can use:

- Letters, digits, `_`, `$`
- Cannot start with a digit
- Cannot be reserved words (`let`, `function`, `while`)

Use camelCase by convention:

- Preferred: `lastPrice`
- Avoid: `LastPrice`, `last_price`

## 1.15 Event-Driven Programming

An event is an action the browser responds to.

Examples:

- Mouse movement
- Key press
- Form submission
- Network response

Event timing is often unpredictable, so code reacts when events happen.

---

## Events and Event Handlers

Event-driven programming means code runs in response to events.

Code that runs for an event is called an:

- Event handler
- Event listener

The browser detects events and calls the handlers you register.

---

## Focus and Blur Example

```javascript
const box = document.querySelector("#username");

box.addEventListener("focus", function () {
  box.style.borderColor = "#2ecc71";
});

box.addEventListener("blur", function () {
  box.style.borderColor = "#e74c3c";
});
```

`style` changes inline CSS, so the input border updates immediately.

---

## Common Browser Events

- `change`: value modified and committed
- `input`: value changes while typing/editing
- `load`: page and dependent resources loaded
- `DOMContentLoaded`: HTML parsed and DOM ready
- `focus`: element becomes active for keyboard input
- `blur`: element loses focus
- `submit`: form is submitted

---

## Three Ways to Register Handlers

1. HTML attribute (avoid when possible)
2. DOM property assignment (single handler)
3. `addEventListener()` (preferred)

Best practice: use `addEventListener()` for separation of concerns and multiple handlers.

---

## 1) Embedded in HTML (Least Preferred)

```html
<button onclick="clickHandler()">Click Me</button>
```

Why avoid it:

- Mixes content and behavior
- Harder to maintain at scale

---

## 2) DOM Property Assignment

```javascript
const btn = document.querySelector("#myButton");
btn.onclick = clickHandler;
```

Better than inline HTML, but assigning again overwrites previous handler.

---

## 3) addEventListener() (Preferred)

```javascript
const btn = document.querySelector("#myButton");
btn.addEventListener("click", clickHandler);
btn.addEventListener("click", logClick);
```

Advantages:

- Multiple handlers per event
- Cleaner separation of HTML and JavaScript

---

## Event Object, target, and this

Handlers can receive an event object with details about the event.

```javascript
function keyupHandler(event) {
  console.log(event.target.value);
  console.log(this.value);
}

document.querySelector("#pw").addEventListener("keyup", keyupHandler);
```

Inside this handler, `event.target` and `this` both refer to the input element.

---

## Preventing Default Behavior

Use `event.preventDefault()` to stop browser built-in behavior.

Common uses:

- Stop form submission for client-side validation
- Block unwanted key input
- Control link/button behavior in SPA interactions

---

## Stopping Propagation

Use `event.stopPropagation()` to stop traversal in capture/bubble phases.

Important detail:

- Browser stops moving event to other nodes
- Handlers on the current node can still run

---

## Password Example: preventDefault + input

```javascript
const pw = document.querySelector("#password");
const strength = document.querySelector("#strength");

pw.addEventListener("keydown", function (event) {
  if (event.key === " ") {
    event.preventDefault();
  }
});

pw.addEventListener("input", function () {
  if (pw.value.length < 6) {
    strength.textContent = "Weak";
  } else if (pw.value.length < 10) {
    strength.textContent = "Moderate";
  } else {
    strength.textContent = "Strong";
  }
});
```
